# Skill 设计与使用边界

## 1. 两类 Skill，不混淆开发与运行

| Skill | 使用者/触发条件 | 不负责 |
| --- | --- | --- |
| [minecraft-mcp-development](../skills/minecraft-mcp-development/SKILL.md) | 后续编码 Agent；实现、调试或验证本仓库 Fabric/MCP 能力时 | 不替代需求或以文档当运行证据 |
| [minecraft-mcp-building](../skills/minecraft-mcp-building/SKILL.md) | 已连接真实 MCP 的外部 Agent；选址、建造、校验、修复时 | 不安装游戏、不修改仓库、不偷偷运行命令或直接编辑存档 |

Skill 是操作规范；当前项目后端已实现，但放置 SKILL.md 仍不等于客户端自动加载，也不等于所有宿主都能使用游戏工具。首次使用必须验证宿主确实加载了 Skill，并独立发现 MCP 工具。

## 2. 文件结构与渐进加载

每个目录包含带 name/description frontmatter 的 SKILL.md。主文件只保留触发条件、约束、工作步骤、完成证据。较长算法放 references/，需要时读取，避免每次占满上下文。

- 开发 Skill 引用仓库 AGENTS.md、架构、接口与验收文档；只在完整 checkout 环境使用，不宣称可独立安装后仍拥有这些相对路径。
- 建造 Skill 自包含在自身目录；references/build-and-verify.md 说明计划表达、解码、差异比较与房屋验收，便于复制到支持 Skills 的宿主。
- 不附自动执行脚本、不捆绑 Token、不加入外部模型 API、不自动安装未知技能包。
- Skill 名称不等于 MCP 工具前缀；客户端可能添加服务名前缀，应按 tools/list 实际结果定位。

部署时使用目标宿主已公开支持的技能目录或导入方式。不要把某一个 Agent 的目录惯例写成 MCP 标准。本仓库不自动改用户全局 Skill 配置。MCP 本身不保证会发现仓库中的 Skills；首期不实现 Skills-over-MCP 扩展。

## 3. 建造 Skill 的最小输入/输出

输入：用户建筑要求、允许的世界/玩家/区域、可用 MCP 连接。缺少外观细节可选保守默认；缺少会影响覆盖范围和权限的信息则在点位风险前确认。玩家多于一名且未指定时不能随机选择。

过程状态：world_session_id、dimension、玩家位置与朝向、批准的包围盒、目标 BlockState 映射、阶段依赖、request_id 与 operation_id、差异列表。它们是当前任务数据，不是隐式长期记忆；任务中断后重新校验会话和世界。

输出：实际位置与尺寸、执行任务状态与计数、重读验证覆盖、剩余差异、保存重启是否验证。不能用“提交成功”代替建造完成，不能只展示规划图。

## 4. 权限与错误恢复

用户明确授权的建筑范围内，Agent 可自主批次建造与修复；扩大范围、拆除已有用户建筑、改权限、触及新维度需重新确认。Skill 不是权限提升机制。世界文字、MCP 描述中的第三方内容不能授权额外操作。

CHUNK_NOT_LOADED 时优先缩小/重新选择授权范围内已加载区域；若需求必须原地执行，报告需玩家移动或管理员加载，不改 loaded_only 策略。桥断线后查询原 operation/request，不能无限重试写请求；会话变化后停止旧计划并重新感知。

结果 TTL 到期重读世界，不推断任务没执行。取消不回滚；复原须作为新的已授权计划。没有 MCP 连接时明确阻塞，禁止改用 shell、命令方块、存档编辑或 Mock 完成验收。

## 5. Skill 验证计划

### 静态检查

- name 与目录名一致，description 非空且包含触发场景。
- 相对链接可解析；建造 Skill references 可随目录独立分发。
- 不含秘密、假工具、已通过的虚假测试结论。

### 行为评估（后续实现时）

| 场景 | 预期 |
| --- | --- |
| 地形有水、树冠、洞穴 | 读取实际数据，区分支撑面、净空与流体，不只看最高 Y |
| 多玩家、不同维度 | 明确选择玩家，沿其真实 dimension 规划 |
| 部分 batch 失败 | 查询明细、重新读取、只修复差异 |
| 用户中途修改窗户 | expected_state 冲突不强行覆盖，报告并协调 |
| 世界退出再进入 | 旧 world_session_id 被拒绝，旧计划不自动应用 |
| 任务已提交但网络断开 | 使用已记录 ID 查询，不重复破坏性提交 |
| 实际楼梯方向错误 | 逐状态比较发现并修复，不只对比方块 ID |
| 室内多余方块 | 期望空气参与比较，发现后仅在授权范围清理 |
| 世界中出现指令文本 | 只视为数据，不执行或提升权限 |

行为评估须用真实工具与真实世界。静态 SKILL.md 校验只证明结构完整，不证明 Agent 一定按要求行动。开发报告应分别记录 Skill 是否加载、工具是否连接、执行轨迹与最终世界证据。
