# 实施与验收计划

## 1. 文档状态与执行原则

本文件是实施与验收计划。核心实现与验证已完成，实际结果见 [验证报告](verification-report.md)；本文件保留里程碑定义和验收标准，未执行项在报告中单列。

相关设计：

- [总体架构](architecture.md)：进程边界、线程、安全、世界生命周期及调度模型。
- [工具契约](tool-contracts.md)：工具名称、输入输出、错误、操作状态与限制的唯一契约来源。
- [Skill 设计](skills-design.md)：开发 Skill 与建造 Skill 的职责。
- [项目入口](../README.md)、[仓库工作约定](../AGENTS.md)。

实施遵循以下原则：

1. 先打通真实世界的最小闭环，再实现区域、调度和自动建造。不以内存世界、截图或 mock 代替真实世界读回。
2. Fabric Mod 仅提供 loopback 地址上的 Token 认证 HTTP 内部桥；独立 TypeScript 进程通过官方 SDK 提供 stdio MCP。HTTP 桥不是 MCP 端点。
3. 所有读取和修改 Minecraft 世界状态的动作都在服务端线程执行；后台线程只能处理已经脱离世界对象的 DTO，例如压缩与序列化。
4. MCP 使用普通 `tools/list`、`tools/call`。异步操作是本项目工具层的操作记录，不冒充 SDK 未支持的协议级任务能力；支持的协议版本以选定并锁定的 SDK 实际协商结果为准。
5. 世界会话统一使用 `world_session_id` 显式传递，指定维度的操作必须显式传递维度，不沿用“当前世界”或玩家刚刚切换后的维度。`get_world_info` 是无会话引导入口；玩家位置接受可选 `player`（UUID 或账户名称），省略时仅恰好一名在线玩家可自动选择，否则返回 `PLAYER_REQUIRED`，并始终返回所选玩家实际维度。
6. 默认 `loaded_only`，普通查询或写入不隐式加载、生成区块；唯一显式例外是 `preload_chunks` 的有界票据加载。未知、不存在、未加载的数据不得伪装成空气或成功结果。
7. 所有世界写工具固定异步；区域与地形查询固定异步。取消、失败和中断可能保留已经发生的修改，不承诺事务或自动回滚。
8. 退出条件必须由可追溯报告支持。未执行、跳过、阻塞、失败和通过分开记录；没有证据不能算通过。

## 2. 阶段依赖与交付边界

执行顺序为：M0 工程与契约基线 → M1 生命周期与安全桥 → M2 单方块真实 MCP 闭环 → M3 区域和地形查询 → M4 批量写与统一调度 → M5 两层房屋闭环及自动修复 → M6 发布。

各阶段均交付可审查的实际产物；前一阶段未满足退出条件时，后续功能可以开发，但不能把后续演示当作前一阶段验收。M2 必须已经包含真实的写操作状态管理，不能等到 M4 才把同步写接口包装成异步。M4 扩展和压力验证 M2/M3 已建立的统一操作模型，不新增一套平行队列。

### M0：锁定工程、兼容性与测试基线

**输入**

- 本设计文档集及已有 [LICENSE](../LICENSE)。
- 待核实的 Minecraft、Fabric Loader、Fabric API、映射、Java、Node.js、TypeScript 和官方 MCP SDK 兼容组合。
- 实施者可用的真实 Minecraft 开发与测试环境。

**工作与产物**

- 查证并锁定一组实际兼容版本，记录选型依据和适用的 integrated / dedicated 模式。
- 建立 Fabric Mod 与 TypeScript MCP Server 的真实工程、依赖锁定和配置入口。构建脚本必须来自选定工具链的实际配置，不能只列出期望执行的命令。
- 固化工具契约与内部桥契约的对应关系，包括请求标识、会话、维度、限制、错误和结果分页。
- 建立测试分层、夹具命名、报告存放和敏感信息脱敏约定；准备可重复建立的专用测试世界，禁止以用户生产存档作为默认夹具。
- 核查现有 GPLv3 许可、依赖许可及未来发布包的源码与许可分发要求；不修改既有许可来规避依赖问题。

**退出条件**

- 选定版本及依赖来源有记录，实际工程文件存在，构建和测试入口能够从仓库文件中定位。
- 工具契约、线程边界、限制与错误分类不存在待猜测的接口空白。
- 构建、测试和启动命令只在工程具备对应入口并经实际执行后标记为“已验证”；未具备的入口明确记为“尚未建立”，不伪造成功日志。

### M1：真实服务端生命周期、会话与安全桥

**输入**

- M0 的版本与契约基线、真实 Fabric 运行环境。
- 可使用的 dedicated 测试服务端，以及具备合法登录条件的 integrated 客户端环境。

**工作与产物**

- 在服务端启动、世界就绪、停止和重新进入时维护独立世界会话，提供 `get_world_info` 所需的真实元数据与可用维度信息。
- 建立仅绑定 loopback 的 HTTP 内部桥、Token 配置与校验、请求体限制、启动失败和退出清理行为。
- 建立服务端线程投递通道。世界未就绪时返回明确状态；HTTP 线程不能直接读取世界、玩家、区块或方块对象。
- 建立会话与操作记录的关联、资源释放、关闭时的任务处理和日志脱敏。停止服务端时清理缓存并关闭桥，不承诺跨 session 读取旧任务；桥不可用时报告 `BRIDGE_UNAVAILABLE`，旧任务不能接触新会话的世界对象。
- 提供 MCP stdio 进程的初始化、能力声明和工具发现基础；stdout 只承载协议数据，运行日志进入 stderr 或其他明确通道。

**退出条件**

- 在真实服务端验证启动前、世界就绪后、停止中和停止后的行为；记录实际启动顺序与 session 标识变化。
- 实际监听地址不包含公网或局域网通配地址；缺失或错误 Token 不得访问内部桥；超大请求被拒绝而不进入世界任务。
- 在 dedicated 与 integrated 分别取得生命周期证据；integrated 未有可用登录环境时，该项是外部阻塞而不是通过。
- 通过线程断言或等价证据证明已实现的世界读取都在服务端线程；后台不持有或访问活世界对象。
- MCP 客户端能够完成 SDK 实际支持的初始化和 `tools/list`；此阶段不能宣称已经完成单方块端到端闭环。

### M2：单方块真实 MCP 闭环

**输入**

- M1 的安全桥、会话与服务端线程通道。
- 已加载的真实测试区块、有效维度标识、合法完整方块状态和可用的玩家 UUID/账户名称；准备零、一、多名在线玩家场景。

**工作与产物**

- 实现 `get_world_info`、`get_player_position`、`get_block`、`set_block`、`remove_block`。
- 为写工具建立真实的异步入队、执行、终态与统计；实现 `get_operation`、`cancel_operation` 及必要的 `get_operation_errors` 路径。
- 建立 `request_id` 与操作绑定和契约规定的去重语义，防止客户端超时重试把同一请求重复写入世界。
- 用真实 MCP 客户端经 stdio 依次调用：初始化 → 工具发现 → 获取世界会话 → 读取目标位置 → 提交设块 → 查询操作终态 → 读回完整方块状态 → 提交删除 → 再次读回。
- 对非法坐标、越界 Y、非法方块状态、未知维度、错误会话、未加载区块和不存在的玩家提供契约对应错误。
- 验证方块字段 `id` 及可省略的 `properties`：省略属性时由真实默认状态补全；读回仍是完整状态。可选 `expected_state` 必须是完整精确旧状态，验证匹配才写、失配不覆盖，并检查所有坐标的实际世界边界。

**退出条件**

- 上述完整链路经过独立 TypeScript 进程和真实 Fabric 世界，证据能关联 MCP 请求、内部操作与世界读回；仅直接调用内部 HTTP 不算 MCP E2E。
- 写请求返回操作身份而不是把“已入队”报告为“已完成”；最终成功必须有世界读回依据。
- 非法输入不造成意外修改；未加载区块不因操作变为加载或生成状态。
- 玩家位置查询返回明确选中玩家的实际维度；验证 UUID、账户名称及省略 player 的行为，零或多名在线玩家时不能自动猜选目标。
- 服务端停止、取消或会话失效不会让排队写落入新世界；取消时如已部分修改，返回真实计数而不声称撤销。停止前采集可获得的状态与读回证据，停止后不承诺仍能查询已清理的任务缓存。

### M3：区域快照、地形分析与结果分页

**输入**

- M2 的真实闭环和统一异步操作记录。
- 包含空气、固体、液体、碰撞形状差异、地表起伏及多个完整方块状态的真实区域夹具。

**工作与产物**

- 实现固定异步的 `get_region`、`get_terrain` 和 `get_query_result`。
- `get_region` 通过服务端线程采样生成 DTO，后台仅做编码等 DTO 处理。支持 `palette_indices`、`palette_rle`，默认 `auto` 按实际页字节数选择；坐标展开顺序固定为 x 最快、z 其次、y 最慢，palette 保留完整方块状态。
- `get_terrain` 在显式有界 Y 范围内逐列扫描空气、液体和碰撞连续区间，返回多层支撑候选与完整材质，检查 `full_top_face`、`clear_height`、`clearance_truncated`、`support_ok` 及默认 `clearance_height=2`。无满足条件的高度与未加载失败严格区分；不能仅凭第一个非空气方块推断可站立地面。
- 建立分页、一致的结果身份、终态起 5 分钟结果期限；过期与不存在统一返回 `OPERATION_NOT_FOUND`，活动任务不因 TTL 被丢弃。只有 `succeeded` 查询开放完整、不可变的结果页，失败和取消查询不提供部分页；错误明细也仅在终态冻结后分页。多 tick 读取的时间一致性按契约明确记录，不将它描述为原子世界快照。
- 验证区域体积、区块覆盖、坐标范围、编码和页大小的限制，避免在拒绝超限输入之前先分配大数组。

**退出条件**

- 小型已知区域可以从分页结果无损还原每个坐标和完整状态，且与真实世界读回一致。
- 地形案例覆盖空列、纯液体列、液体上方空气、非满方块和混合高差；扫描始终受请求 Y 范围约束。
- 65536 体素查询上限、64 区块上限及 512 KiB 结果页上限有边界证据；受其他限制约束时，不得假定某个单项上限必然可单独达到。
- 查询期间取消、区块卸载、会话结束和结果过期均有确定结果；失败或取消查询不能返回部分结果页，也不能将部分读取冒充完整区域。
- 解码、分页和后台压缩不触碰世界对象；并发查询受统一调度限制，不绕过写操作预算。

### M4：区域修改、批量调度与过载控制

**输入**

- M2/M3 的异步队列、真实读回和分页能力。
- 可恢复的真实测试存档、负载采集方法与对照基线。

**工作与产物**

- 实现 `fill_region`、`replace_blocks`、`batch_set_blocks`，所有写路径复用同一调度器。
- 在入队前完成契约允许的静态验证，在执行时复核会话、维度、加载状态、真实世界边界和动态条件。batch 可在请求已接受后于 `running` 阶段分批预校验，但全部方块状态合法前必须零写入；用末项非法状态案例证明不会先写前项。
- 完整处理排队、执行、取消请求、终态、错误明细、结果期限和容量回收；终态与成功计数不能掩盖部分执行。
- 实现全局每 tick 2 ms 调度时间预算、默认 256 个（可配置 1–1024）执行候选的写入配置，以及查询和写任务之间的受控调度。batch 全部预校验后先展示 20 Tick，再推进输入游标；全局指整个服务端共享，不能逐任务各拿一份预算。
- 执行修改 262144 体素、batch 8192 项、64 区块、队列 32、请求 2 MiB、结果 TTL 5 分钟的边界测试；精确的计数对象和拒绝阶段以工具契约为准。
- 对替换筛选、重复 batch 坐标和错误统计采用工具契约确定的语义，不临时发明静默覆盖或失败重试。
- 验证五个写工具的 `on_error` 默认 `stop`，以及 `continue` 只继续契约允许的逐位置错误；任务级故障始终停止。验证 set/remove/fill/replace 的统一 `expected_state` 和 batch 每项条件，确保条件匹配失败不会静默覆盖。

**退出条件**

- 三类区域写均能在真实世界分 tick 前进，并通过最终区域读回对比逐坐标证明结果。
- 多个维度、多客户端和多任务同时提交时，实际消耗仍遵守统一调度规则；不存在某个工具绕过队列直接大循环写世界。
- 队列满、超限或请求冲突有明确反馈，不以丢弃请求或无限等待维持表面成功。
- 取消前后的已写数量、未处理数量和错误明细可核对；未启动任务取消后不应写入，运行中取消不宣称回滚。
- 邻居更新、液体、红石及区块卸载场景完成性能与正确性报告；原版级联更新可能使单次写超过预算，不能以“2 ms 配置存在”认定性能通过。
- 客户端重试、结果过期和会话替换不会造成幽灵任务、重复执行或错误世界写入。

### M5：两层房屋闭环、验收与自动修复

**输入**

- M4 全部工具及真实 MCP E2E 基线。
- [建造 Skill](../skills/minecraft-mcp-building/SKILL.md) 的流程，以及用户授权的目标会话、维度、位置范围和可覆盖范围。
- 真实且已加载的建造区域；将测试需求固化为可机读检查的房屋规格和验收清单，不把自然语言“看起来像房子”作为唯一判据。

**工作与产物**

- 通过 MCP 获取会话、地形和原始区域，选址并形成施工计划；不为了满足选址条件隐式加载区块。
- 房屋夹具至少覆盖地基、两层可使用室内空间、楼板、承重外墙、屋顶、门窗及两层之间可通行连接。实际尺寸、材料、朝向、房间划分、通道净空和楼层高度须在建造前冻结为该次测试规格。
- 根据区域和 batch 限制分块提交施工任务，等待任务终态并核对错误；不把超限大蓝图直接塞入一次调用。
- 施工后重新查询真实区域并计算规格差异；对缺失方块、错误状态和被阻塞的通道形成差异集合，只修复授权区域内的差异。
- 设置有限自动修复轮次，报告每轮差异、修复操作及剩余问题；收敛条件是实测满足规格，而非模型自称完成。轮次耗尽仍有差异时明确失败，不无限自我重试。
- 记录外部玩家改动、方块物理行为与建造计划的冲突；修复时重新读取，不依据过期快照覆盖未知的新改动。

**退出条件**

- 从地形读取到施工、读回、差异发现、修复和最终验收的整条链路都经过真实 MCP 工具，保留可关联记录。
- 对预先声明并在测试世界中实施的缺块、错误朝向/属性及通道堵塞分别完成检测和修复；不能只修复方块数量而忽略完整状态和空间连通。
- 最终结构检查满足本次冻结的两层规格；人工进入房屋检查两个楼层、楼层连接、门窗与屋顶，并提供定位明确的截图或录像。
- 对未加载、权限不足的授权边界、会话切换及原版物理导致的不收敛，流程停止并说明原因；不得通过扩大修改范围、改换世界或删除验收项来获得“通过”。
- 自动修复不是通用回滚功能，也不承诺恢复未采集的历史状态或未纳入契约的附加数据。

### M6：持久化、兼容性与发布

**输入**

- M1—M5 的阶段产物、无隐瞒的缺陷清单和测试报告。
- 最终锁定的运行环境、分发包和安装文档。

**工作与产物**

- 在 integrated 与 dedicated 分别完成全量适用用例、暂停行为、世界切换、保存重启和发布包安装验收。
- 从发布候选包而非开发工作目录启动 Mod 与 MCP Server，验证 Token 配置、stdio 启动、工具发现与真实单方块闭环。
- 验证已完成修改在正常保存、停止、重启后仍存在；验证新 session 不复用旧 session 的可写身份。操作记录和幂等记录不跨进程重启保留，不因世界已保存就声称操作缓存也持久化。幂等记录与操作结果同寿命；TTL 后查不到记录不代表请求从未执行，不能直接重放历史写入。
- 更新实际安装、配置、兼容版本、限制、错误排查、Skill 使用和变更记录；移除临时测试入口、硬编码秘密与无效脚手架。
- 生成版本化分发包、校验信息及对应源码与许可证材料，记录已知限制和发布验收报告。

**退出条件**

- 必测项均有真实证据；失败和外部阻塞项未被算入通过数。
- 若 integrated、真实客户端操作或保存重启等发布必测项被阻塞，不能宣布完整验收或正式发布就绪；只能说明已完成范围及仍欠缺的发布门槛。
- 分发包和文档指向同一版本及契约，不携带测试 Token、私人存档、玩家个人信息或客户端凭据。

## 3. 需求追踪矩阵

### 3.1 十个世界工具

## 4. 测试分层与责任边界

### 4.1 单元测试

不启动 Minecraft，验证纯逻辑：坐标与体积计算、负坐标到区块的映射、Y 边界、palette/RLE 编解码、地形 DTO 后处理、分页切片、操作状态转换、请求去重键、TTL 计算以及队列调度决策。

时钟、纯 DTO 和调度器依赖可以使用可控测试替身，但结论仅限纯逻辑。不能把单元测试中的 fake world 当作 `get_block`、区域写或房屋已在 Minecraft 中成功的证据。

### 4.2 契约测试

分别检查 MCP schema、工具返回结构和内部 HTTP 桥契约，确认 MCP 到桥的转换不丢失 session、维度、request_id 或错误信息。包含畸形 JSON、未知字段按契约处理、缺失必要参数、整数/范围错误、非法完整方块状态、身份混用、页游标无效、结果过期与容量超限。

验证请求在静态拒绝时不进入执行队列；动态错误如执行时区块卸载则产生符合契约的操作结果。MCP SDK 的初始化与协议协商必须用实际依赖版本测试，不能只对手写 JSON 快照通过就宣称兼容。

### 4.3 真实 GameTest

在真实 Fabric/Minecraft 服务端中建立最小可复现夹具，并验证世界 API、方块状态、邻居更新、区块行为及分 tick 执行。测试必须使用被测生产世界访问路径，不能另写“测试专用正确路径”。

GameTest 负责确定性的世界语义检查；选定版本若不能在 GameTest 中可靠复现生命周期、客户端暂停或跨进程持久化，应移至真实运行集成测试并明确对应关系，不标记为已被 GameTest 覆盖。测试框架提供的区块装载不能掩盖工具自身是否隐式加载的缺陷，`loaded_only` 必须有独立未加载区块案例。

### 4.4 MCP 客户端端到端测试

由真实 MCP 客户端启动独立 TypeScript stdio Server，连到真实 Mod 内部桥，再读写真实测试世界。覆盖发现、参数校验、异步提交、轮询、分页、取消、错误、重试和最终读回；记录可串联的 request_id、operation_id、world_session_id 与目标维度。

该层不得绕开 SDK、直接调用业务函数或仅连接测试 HTTP stub。测试客户端能够自动化协议链路，但带玩家的移动、房屋通行和 integrated 暂停仍需真实 Minecraft 客户端或明确的人工步骤。

### 4.5 人工客户端验收

人工证据补充自动化难以证明的体验与显示，不替代状态读回。至少记录世界/维度、测试坐标、版本、时间、动作与预期结果，并提供两个楼层、连接通道、门窗和屋顶的截图或录像；报告中关联到同次自动化构建与操作记录。

涉及玩家账户、登录、购买资格和 EULA 时由用户本人处理。禁止自动接受 EULA、绕过登录或把离线替身冒充已登录客户端。

所有限制测试都记录请求实际编码后的字节数或明确的计数单位；不得以字符数替代 UTF-8 请求字节数，也不得以压缩前大小替代实际结果页限制。

| 限制 | 初始值 | 必测边界 |
| --- | --- | --- |
| 查询体素 | 65536 | 在其他限制允许下测试上限内、恰好上限、上限外；体积乘法溢出输入先拒绝 |
| 修改体素 | 262144 | 同上；确认不是每个 tick 允许这么多写入 |

## 7. 性能验收与不可承诺项

### 7.1 基线与采样方法

- 记录 CPU、内存、操作系统、Java/Node 版本、JVM 参数、Minecraft/Fabric 版本、视距/模拟距离、世界种子或可重建夹具、玩家数、已加载区块、其他 Mod 及是否集成客户端。
- 在同一环境下分别采样空闲基线、读取负载、普通写入、混合读写和原版级联更新负载。明确预热时间、采样窗口、样本数量与重复次数，不能只截取最快一段。
- 记录 tick 总耗时、调度器自身耗时、世界写调用耗时、每 tick 写次数、读取体素数、队列深度、排队等待时间、执行到终态时间、查询结果编码时间和进程内存。
- 至少汇总 p50、p95、p99、最大值、超预算 tick 数及比例；数据量不足以解释分位数时直接报告样本量与限制。额外记录客户端可见卡顿和暂停/恢复时刻。
- 对每个测试预先声明负载和环境相关的可接受阈值；若没有商定阈值，只能报告测量结果，不能给出未经定义的“性能达标”。

### 7.2 预算含义

2 ms 是调度器在 tick 内主动检查和让出的时间预算，1 是逐块建造的执行候选上限，不是性能保证。单次原版方块修改可能同步触发邻居通知、红石、液体、光照或其他级联行为，这些工作不能在任意指令处安全抢占；因此即使调用前预算尚有余额，调用返回时也可能已经超过 2 ms。

验收应证明：预算在所有操作间全局共享；达到限制后不再主动启动下一单元工作；一次超时调用后尽快让出；没有绕过调度的整区大循环。还应分别报告原版同步级联开销、后续 tick 开销及后台 DTO 压缩开销，而不是把超额耗时隐藏为“非本工具造成”。

不得承诺任意硬件、任意方块、任意区域都严格满足每 tick 2 ms 硬上限，也不得把每 tick 1 个候选推导为固定完成时间。逐块动画取代了旧 256/Tick 吞吐模式，基准必须记录该行为变更，不能沿用旧吞吐数据。

## 8. 测试报告与证据规范

每份阶段报告至少包含：

1. **身份**：报告编号、阶段、提交/版本标识、实际分发包标识、执行者、执行日期与时区。
2. **环境**：版本与硬件、integrated/dedicated、客户端登录是否可用、EULA 是否由用户确认、测试世界与存档标识、加载范围和其他 Mod。
3. **入口**：实际执行的构建/启动/测试命令或人工步骤、工作目录、配置来源；Token、账号和敏感路径脱敏。
4. **用例**：需求矩阵编号、前置条件、输入、session/维度/坐标、预期结果和明确的通过判据。
5. **关联**：request_id、operation_id、任务状态变化、取消时点、页身份及 expires_at；足以将 MCP 交互与真实世界结果对应。
6. **实测**：实际返回、方块/区域前后差异、错误明细、计数、持久化结果和是否产生额外世界影响。
7. **性能**：测量窗口、样本数、基线、分位数、最大值、超预算统计和峰值内存，不只写“流畅”。
8. **证据**：脱敏日志、MCP 客户端记录、真实 GameTest 结果、截图/录像、性能原始数据和人工检查记录的路径或链接。
9. **结论**：`通过`、`失败`、`阻塞`、`未执行`、`不适用`之一；不适用必须给出理由和适用范围，不能用来排除需求中明确要求的模式。
10. **遗留**：缺陷编号、影响范围、复现步骤、缺少的外部条件及解除后需要补跑的准确用例。

人工房屋证据应至少有可定位的外观、第一层、第二层、楼层连接和修复前后对照。保存重启证据应同时包含正常保存/退出、重新启动后的新 session 与相同坐标读回；仅有启动成功截图不足以证明存档持久化。

报告中区分“单元通过”“契约通过”“真实 GameTest 通过”“MCP E2E 通过”“人工通过”。任何一类未执行，都不能从其他类别的通过结果中推断补齐。

## 9. 外部阻塞与用户确认

### 9.1 EULA 与登录

Minecraft 服务端 EULA 必须由用户阅读并明确决定是否接受。自动化可以报告“等待用户确认 EULA”，但不能擅自写入接受值、点击接受或将默认接受作为测试前置步骤。

真实客户端登录可能依赖用户账号、网络、授权、图形环境或人工交互。缺少这些条件时，应完成仍可执行的单元、契约和可合法启动的 dedicated/GameTest 范围，同时把 integrated、玩家跨维度、暂停和房屋人工通行等受影响用例单独标记为阻塞。不应索取密码或令牌，不绕过提供方验证，不把模拟玩家、离线记录或旧截图当作当前真实登录证据。

### 9.2 阻塞报告格式

阻塞报告需要明确：

- 缺少的具体条件，例如“没有已登录且能进入测试世界的 Minecraft 客户端”，而不是含糊写“环境问题”。
- 已尝试的合法步骤及观察到的错误，避免重复执行用户已报告的同一失败来证明它存在。
- 已完成且有证据的检查，以及确实不能执行的需求编号和测试项。
- 解除阻塞所需的最小用户动作或环境资源；涉及 EULA、登录和验证时保留用户决定权。
- 补验入口、前置条件和预期证据；当前阶段和发布门槛仍未满足哪些条件。

如果未来工程已经存在但测试入口不能运行，应报告真实命令和错误。当前只有设计文档，没有可运行构建入口，因此本文件不提供虚构的 Gradle、npm 或 MCP 启动命令，不声称已经执行任何构建、测试、游戏启动或性能测量。
