# Minecraft MCP 开发

## 先读什么

在完整仓库 checkout 中使用本 Skill。先读 [AGENTS.md](../../AGENTS.md) 和 [README](../../README.md)，按任务读取 [架构](../../docs/architecture.md)、[工具契约](../../docs/tool-contracts.md)、[实施验收](../../docs/implementation-plan.md)。核心实现已存在；先检查实际代码与验证报告中的当前证据，不把历史结论当作本次变更的验证。

## 必须保持的不变量

- MCP 使用官方 SDK；内部 HTTP 不冒充 MCP。
- 所有世界读取/修改仅服务端线程，后台仅处理已复制的值数据。
- 使用真实注册表和世界；不要假数据、默认空气兜底或吞异常。
- 区块 loaded_only，不隐式同步加载或生成；不硬编码主世界高度。
- 读写都采用有界预算；大型预校验也分批，防止任务尚未开始就阻塞 Tick。
- 任意失败/取消可以部分修改，准确计数、不自动回滚。
- 大查询明确增量一致性；分页同一不可变结果，不分页重读世界。
- loopback + Token + 有界资源；不将凭据提交或写日志。
- 已完成内存写入不是已保存磁盘；持久化须保存重启再读。

## 实施步骤

1. 对照当前里程碑确认最小可运行切片、对应契约和验收，不先铺空接口。
2. 若初始化工程，核实最新正式版依赖组合，锁定 JDK/Gradle/Loom/Loader/API/SDK；保留现有 LICENSE。
3. 查找并复用已有代码与命名，明确要变更的调用者和 Schema。
4. 为边界/错误/状态转换编写有消费者意义的测试；不要以 source text 或 mock echo 证明行为。
5. 实现完整切片，包括错误、队列、取消、世界生命周期和资源释放。
6. 执行对应构建与测试，再运行真实 Mod 与独立 MCP Client 走受影响路径。
7. 保存真实输出与环境信息；文档、契约、客户端示例随代码更新。

## 验证与停止条件

每次报告分开列出：已实现、已运行验证、未运行及具体阻塞。编译通过不证明游戏功能；内部 Java 调用通过不证明 MCP 可连接。不得自动接受 Minecraft EULA、自动登录或伪造这些前提。

外部阻塞时先完成可验证部分，记录缺少的授权/环境和已尝试步骤。不要使用 Mock 替代游戏验收，不把计划中的命令写成已成功运行。
